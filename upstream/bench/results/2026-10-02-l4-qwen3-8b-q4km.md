# A/B: VLLM_GGUF_DENSE_GEMM_MIN_ROWS 0 vs 1024 — L4, 2026-10-02

Raw numbers behind draft 06. Reproduce with
`bash upstream/bench/run_ab_dense_gemm.sh` (then `MODE=needle` for the last table).

- GPU: NVIDIA L4 (sm89), Colab. vLLM 0.30.0, torch 2.13.0+cu132.
- Plugin: `main` @ `e2b8ad5` + `upstream/patches/06-dense-gemm-large-batch.patch`,
  built from source; `_C_gguf` loaded (`cuda_ext_loaded True`).
- Model: `unsloth/Qwen3-8B-GGUF:Q4_K_M`, tokenizer `Qwen/Qwen3-8B`.
- Server: `--max-model-len 16384 --max-num-seqs 64 --max-num-batched-tokens 8192
  --gpu-memory-utilization 0.85 --no-enable-prefix-caching`.
- One variable between arms: the env var. Same process order, same prompts (seeded).

## Tests

`pytest tests/test_kernels.py -k dense_gemm`: **73 passed** (67 s).

## Prefill — tok/s, one request at a time, fresh random prompt, `max_tokens=1`

5 timed runs per length after one warm-up; median (min–max).

| prompt tokens | threshold 0 (stock) | threshold 1024 | speedup |
|---|---|---|---|
| ~2,100 | 213 (211–217) | 2,709 (2,701–2,740) | 12.7× |
| ~8,350 | 210 (209–210) | 2,337 (2,116–2,441) | 11.1× |
| ~12,200 | 208 (208–208) | 2,715 (2,685–2,734) | 13.1× |

Wall time for a ~12.2k-token prompt: 58.7 s → 4.5 s.

## Decode — total tok/s, closed loop, 256 fixed-length tokens, 3 requests per worker

| concurrency | threshold 0 | threshold 1024 |
|---|---|---|
| 1 | 41.7 | 42.5 |
| 4 | 111.2 | 111.4 |
| 16 | 173.3 | 172.3 |
| 32 | 179.9 | 180.0 |

No errors, no degenerate outputs in either arm (159 requests each).

## Memory

`nvidia-smi` after the run: 19,998 MiB (threshold 0) vs 20,034 MiB (1024).
No OOM in either server log.

## Output check

- Short greedy prompts (4): byte-identical between arms. Expected and NOT evidence
  for the new path: they have fewer than 1024 rows, so both arms use the fused kernels.
- Long-prompt needle (a 5-digit code buried mid-prompt, ~3.1k and ~9.2k tokens,
  3 each, identical prompts in both arms): **6/6 recalled in both arms.**
  The 12-token continuation is byte-identical in 4/6; in the other 2 the code is
  the same and the wording after it differs (" Okay, let's see" vs
  " Okay, let me try"). The two arms use different kernels for the prefill, so
  bit-exact agreement is not expected.

## Not measured

- Other GPUs, other quant types, MoE models, mixed prefill+decode load.
- Peak transient memory during the dense call (only the post-run reading above).
- `vllm serve` logs "Unknown vLLM environment variable detected:
  VLLM_GGUF_DENSE_GEMM_MIN_ROWS" — a cosmetic warning from vLLM core's env check.
